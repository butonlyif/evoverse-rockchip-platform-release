# Platform Development 2026.11.24 candidate.1

**Qualification: `UNQUALIFIED_NO_BOOT`.** Software checks passed. No board was available, so flash, boot, target application execution and RKNN NPU execution are `NOT_RUN / NO_BOARD`. Do not use this candidate as a hardware-qualified or production image.

Target: WS-E2 module on RK3588J EVM carrier, board revision 1. Check the signed descriptor's target identity before using any asset.

Assets:

- `update.img`: RKAF firmware candidate for the stated target.
- `sysroot.tar`: AArch64 development sysroot exported from the same measured rootfs tree as the firmware.
- `app-builder.tar`: Linux x86_64 OCI archive for AArch64 application cross-compilation.
- `model-builder.tar`: optional host-side AI model conversion and simulation OCI archive; target RKNN execution was not tested.
- `source-compliance.tar`: component inventory, license texts, Buildroot target corresponding-source materials, U-Boot/Buildroot source snapshots and build configuration evidence. It does not contain the Platform generator repository.
- `platform-development-release.json`: Ed25519-signed descriptor binding the exact asset digests, target and qualification state. Verify it with `trust/platform-release-2026-11.pub`.

For a manual download, fetch the signed descriptor and the files it lists from this Release. Compare every file's SHA-256 and byte size with the descriptor before loading or using it. The Gitee mirror provides shards with a reassembly manifest for environments where GitHub downloads are unavailable; reassemble and verify the same descriptor digests.

The currently published SDK v1.0.0 package predates signed-descriptor verification. Its Workbench import path is not qualified for this candidate. Use the manual download and checksum path until an SDK package containing the signed-descriptor consumer is released and verified.

Manual verification from a checkout of this release repository (Python 3.12 with `cryptography==49.0.0`): after downloading all GitHub release assets into `downloads/`, run `python -m scripts.verify_assets downloads/platform-development-release.json downloads`. For Gitee, download `reassembly.json` and every named `.partNNNN` attachment into `shards/`, then run `python -m scripts.reassemble shards/reassembly.json shards restored`. A `PASS` result checks the pinned public key, signed descriptor, every part, and every restored asset. Keep the original `UNQUALIFIED_NO_BOOT` state.
